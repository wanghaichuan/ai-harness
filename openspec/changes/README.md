# changes/ — 变更生命周期目录

> 本目录是所有代码变更的**工件管理入口**：每次变更先在这里创建 change 目录，走完流程后归档。
> 铁律：**没有 change 工件，不允许修改代码。** 归档后仍保留本目录，方便之后的变更。

## 用处

1. **需求先工件化**：任何代码变更（新功能/改造/修 Bug）先在这里落工件，再写代码
2. **范围管控**：只做工件（任务.md）范围内的事，防止需求漂移
3. **评审依据**：评审四连以本目录工件为对照基准
4. **历史追溯**：归档后保留完整决策与设计记录

## 目录结构

```
changes/
├── README.md            # 本文件
├── <中文change名>/      # 活跃变更（一个变更一个目录）
│   ├── 提案.md          #   为什么改、改什么、范围边界
│   ├── 设计.md          #   怎么改：方案、字段映射、接口设计
│   ├── 任务.md          #   拆解清单（可勾选）
│   └── （评审产物）      #   review-summary / architecture-review / sql-review / review-report
└── archive/             # 已完成变更归档
```

## 使用流程（OpenSpec 四步）

```
propose  →  apply  →  verify  →  archive
```

## 命名规范

- **change 目录用中文描述命名**，方便查找
- 三大工件固定文件名：`提案.md`、`设计.md`、`任务.md`
- 评审产物追加在同目录，不与三大工件重名
