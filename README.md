# ai-harness — 可复用 AI 协作工程管理骨架

> **定位**：可复制的 Harness（AI 协作工程管理）骨架。任何新项目只需复制本目录，按 `CLAUDE.md`/`AGENTS.md` 模板填入项目信息即可开工。
> 十六字原则：**需求先工件化，知识先显性化，执行先加护栏，评审与验证必须分离。**

---

## 骨架结构（可复制复用）

```
ai-harness/
├── README.md                # 本文件：复用指南
├── AGENTS.md                # AI Agent 入口导航模板（改「项目身份」即可用）
├── CLAUDE.md                # 行为约束模板（含编码前置动作：codegraph + 记忆；数据库脚本禁止 AI 执行）
├── docs/
│   ├── README.md            # 知识库结构说明（怎么组织 docs）
│   └── guides/
│       ├── AI开发写作维护指南.md  # 标准定位/开发流程/修改/验证/工作流模板
│       └── 复用检查清单.md   # 新项目接入 harness 的检查清单
└── openspec/
    ├── README.md            # 变更工件（提案/设计/任务）中文命名规范
    └── changes/
        └── README.md        # 变更目录用处说明
```

## 核心理念

| 原则 | 落脚点 | 说明 |
|------|--------|------|
| **需求先工件化** | `openspec/changes/` | 每次变更先创建 提案 + 设计 + 任务，再写代码 |
| **知识先显性化** | `docs/` | 架构、隐性约定、产品规则、规范全部写成文档 |
| **执行先加护栏** | `CLAUDE.md` 禁止事项 | 配置保护、数据库脚本人工执行、危险命令拦截 |
| **评审与验证分离** | 评审四连 | 实现与评审由不同 Agent 独立执行 |

## 复用步骤

1. 复制本目录到新项目（如 `<新项目>/repo`）
2. 填 `CLAUDE.md` 的「项目身份 / 模块结构 / 禁止事项」
3. 填 `AGENTS.md` 的导航链接（指向实际 docs）
4. 按 `docs/guides/复用检查清单.md` 逐项核对
5. 安装 CodeGraph：`npm i -g @colbymchenry/codegraph` → `codegraph init` → `codegraph install`

## 开发流程速览

```
① 读需求+原型 → ② 整理接口 → ③ 库设计+脚本 → ④ 跑脚本（人手动执行） → ⑤ 编码
→ ⑥ 接口实现说明与测试用例 → ⑦ 接口测试 → ⑧ 测试报告
→ ⑨ 整合变更工件到 openspec/changes → ⑩ 评审后归档 archive
→ ⑪ 更新业务词索引 + CodeGraph + 记忆
```

详见 `docs/guides/AI开发写作维护指南.md`。

## 维护约定

- 通用约定变更 → 先改本骨架 → 回灌到各使用项目
- 项目专属知识（业务词、隐性约定）→ 只留在项目内，**不要**塞进通用骨架
